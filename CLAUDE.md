# CLAUDE.md

This file guides Claude (and other contributors) working in this repository.

## Standing instruction: keep the docs current

Every change to behaviour, options, thresholds, verdicts, file layout, packaging or dependencies must update **both** `README.md` (the user-facing documentation) and this `CLAUDE.md` (the contributor/agent notes) in the same commit. If you add a CLI flag, document it in the README options table. If you change a detection threshold, update the "How detection works" section of the README and the tunables table below. If you change the GUI, check that the README "Desktop app" section and `docs/gui-screenshot.png` still match it. If you change packaging, update the README "Download" and "Building the packages" sections and `packaging/README-RELEASE.txt`. Add a line to the changelog at the bottom of this file for each notable change, and bump `__version__` in `realhires/__init__.py` and `version` in `pyproject.toml` together.

## What the project does

`realhires` scans audio files or folders and classifies each file as FAKE LOSSLESS (a "fake FLAC": a lossless container with an MP3/AAC source, at any resolution), FAKE HI-RES (upsampled and/or bit-padded), SUSPICIOUS, REAL HI-RES, NOT HI-RES (genuine CD-quality lossless, labelled "CD quality" in the GUI), LOSSY FORMAT or ERROR. Every result also carries a one-line `summary` (the "Why" column) and machine-readable `flags`. It decodes the audio with FFmpeg and inspects the samples, so it never trusts tags or headers. There is a CLI (`realhires`) and a Tkinter desktop app (`realhires-gui`). Both are also shipped as self-contained PyInstaller packages, with FFmpeg bundled, for Windows x64, macOS arm64 (12+), macOS x86_64 (10.15+), Linux x64 and Linux arm64 (glibc 2.28+).

## Commands

| Task | Command |
| --- | --- |
| Run the test suite (about 6 s, it synthesises its own audio with ffmpeg) | `python3 -m pytest -q` |
| Run the CLI from the source tree | `python3 -m realhires PATH... [-v] [--json F] [--csv F] [--plot DIR]` |
| Run the GUI from the source tree (needs Tkinter) | `python3 -m realhires.gui [PATH...]`. Passing paths starts a scan automatically. |
| Install the `realhires` and `realhires-gui` commands | `pip install .` |
| Build, verify and package locally (what CI runs) | `ASSET=RealHiRes-local bash packaging/ci_build.sh`. The output goes to `out/`. Linux builds belong inside AlmaLinux 8 (`packaging/linux/setup_almalinux8.sh`, then `PYTHON=/opt/venv/bin/python`). |
| Check binary compatibility of a build | `python packaging/check_compat.py dist/RealHiRes --max-glibc 2.28`, or `... dist/RealHiRes.app --max-macos 12.0 --arch arm64` |
| Smoke-test a built package | `python packaging/smoke_test.py dist/RealHiRes/realhires-cli` |
| Regenerate the app icon | `python packaging/make_icon.py`, which writes `realhires/assets/icon.png` |
| Publish a release | Bump `__version__` and `pyproject.toml` `version` together, add a changelog line, and get the commit onto `main`. The `release` job then tags `vX.Y.Z` and publishes the five packages. Pushing a matching tag `vX.Y.Z` works too, and a tag that does not match `__version__` fails the job. |

The runtime requirements are Python 3.9 or newer, NumPy, and `ffmpeg`/`ffprobe` (bundled or on `PATH`). The GUI additionally needs Tkinter (standard library). There are no other runtime dependencies, and plots are hand-written SVG or Tk canvas, so matplotlib is not needed. Keep it that way unless there is a strong reason.

## Layout

| File | Role |
| --- | --- |
| `realhires/probe.py` | Contains `find_tool()`/`tool()` (FFmpeg lookup order: `$REALHIRES_FFMPEG_DIR`, then the PyInstaller bundle `_MEIPASS/ffmpeg`, then `ffmpeg/` next to the executable, then `PATH`), `probe()` (ffprobe to `AudioInfo`), and `iter_pcm()`, which streams decoded audio as left-justified int32 `(frames, channels)` blocks. `LOSSY_CODECS` lives here. `_no_window()` suppresses console windows on Windows. |
| `realhires/analysis.py` | Contains `SpectrumAccumulator` (streaming Welch spectrum, Blackman-Harris window, about 6 Hz bins; with `spectrogram=True` it also keeps 256 linear bands × one row per 0.25 s, and `spectrogram_result()` returns it as zlib-compressed uint8 dB of at most 1200 columns), `BitDepthAccumulator` (lowest-set-bit histogram), `analyze_spectrum(..., cfg=)` (bandwidth, cliff test with the edge tie-break, lossy cliff scan), `compact_spectrum()` (a 900-point max-hold spectrum for the GUI), and `decode_spectrogram()`. Detection defaults are module constants. `detection_params(cfg)` maps a `Settings` object (or None, meaning the defaults) to the values actually used. |
| `realhires/settings.py` | The `Settings` dataclass, in which every field carries group, label, help, limits and kind metadata that the GUI uses to build its Settings window. | `realhires/imaging.py` | NumPy-only colour maps (inferno/magma/viridis/gray), `spectrogram_rgb()`, `to_ppm()` (which the GUI shows through Tk's PhotoImage), `to_png()`, and `spectrogram_png()`, which draws the axis labels with a tiny bitmap font for CLI `--spectrogram`. |
| `realhires/verdict.py` | Contains `analyze_file(path, max_seconds, keep_spectrum, keep_plot, settings)` (the per-file pipeline, which never raises and turns failures into ERROR; `keep_spectrum` is for SVG, and `keep_plot` puts the compact spectrum plus spectrogram in `FileResult.plot`), `_judge()` (measurements to verdict, reasons, summary and flags; a lossy cut-off always wins and gives FAKE LOSSLESS), `FileResult` (`to_dict()` for JSON/CSV, `is_problem`), `verdict_breakdown()` (count and percentage per verdict, used by the CLI summary and the GUI pop-up), and `VERDICT_ORDER`/`PROBLEM_VERDICTS`. |

| `realhires/fix.py` | "Fix to real resolution". By default it fixes the file **in place** (same name, tags and cover art), so its properties show the real rate and bits, and the original is moved to `BACKUP_DIR_NAME` = "Real-Hi-Res backups" next to the file (`fix_backup`: folder, `.bak` or delete; `fix_backup_folder` for a custom folder). Copies are optional (`fix_output`). Rewriting the audio is required, because only editing the header values would change the playback speed. `target_resolution()` uses the source rate (`upsampled_from`, or the 44.1/48 family for lossy sources) and the real bits (16/24, optionally forced to 16 for CD-sourced files, per `fix_bits`). `plan_fix(result, cfg)` returns `(FixPlan, None)` or `(None, reason)`. `ffmpeg_command()` keeps tags (`-map_metadata 0`), copies cover art for FLAC/M4A, resamples with soxr, and adds triangular dither only for resample-to-16. `run_fix()` writes to a temp file (`.realhires-*`), moves the original to its backup (restoring it if the final rename fails), renames the temp file, and re-analyses the result. `cli.iter_audio_files()` skips the backup folder and the temp files, so fixed originals are never rescanned. `Settings.from_dict()` migrates the 1.4.0 `fix_output` values. |
| `realhires/listing.py` | `list_source()` walks one source in a thread and posts `("listing", source, batch)` every 500 files or 0.25 s, then `("listed", source, None)`. It is cancellable. |
| `realhires/report.py` | Terminal table, summary, JSON/CSV writers, and the dependency-free SVG spectrum plot. |
| `realhires/cli.py` | Handles `iter_audio_files()`/`collect()`, `--fix`/`--fix-dir`/`--fix-replace`/`--dry-run` (`run_fixes()`, which converts in a thread pool), argparse, settings loading (`--settings`, `--no-settings`, `--set`, `--list-settings`), file collection (`collect(paths, recursive, extensions)`), the `ProcessPoolExecutor` fan-out, ordered streaming output, the `FILTERS` aliases for `--only` (`fake`, `problems`, ...), `--spectrogram` PNGs, and the percentage summary with bars. |
| `realhires/gui.py` | The Tkinter app. Adding a folder or file inserts it into the "Sources to scan" `src_tree` and starts a `list_source()` thread, which posts `("listed", source, files)`. The files then appear at once as grey "Not scanned" rows (`PENDING`, which is GUI-only and never a verdict). Empty sources are shown in red, duplicates are ignored, and Remove (or the Delete key) drops a source. `Scanner(files, ...)` analyses exactly the listed files, each result replaces its pending row in place, and the source rows show "x of n" problem counts. Scanning is deferred (`scan_when_listed`) while listing is still running, and changing the extension or recursion settings lists the sources again. Batches from the listing thread are inserted as they arrive. While scanning, `_mark_running()` marks the first `scan_workers` unfinished files in submission order as `RUNNING` ("Analysing…"). Rows are never removed during a scan (`_insert` updates them in place), and filters apply at `_finish`. If the selected row finishes, the dashboard refreshes. `FixDialog` plans with `fix.plan_fix`, runs `run_fix` in a thread pool, shows per-file status, and calls `App.add_fixed_result()`. Fix entry points are the "Fix to real resolution…" button, Ctrl/Cmd+F, the context menu, and Edit → Fix all fake files to real resolution. The `Scanner` thread uses a spawn-context `ProcessPoolExecutor` and a `queue` that `App._poll()` drains every 100 ms. Each result's `plot` goes to `PlotCache`, which pickles it to a temp dir so big libraries do not fill the RAM. It is loaded back when a row is selected. The window has a menu bar (File/Edit/View/Help) and a `ttk.Treeview` list with a "Why" column, filter checkboxes with counts (the defaults come from `settings.shown_verdicts`), search over path and summary, and sortable columns. Below that is the dashboard: a verdict badge, the summary, a facts grid, Open Folder / Open File / Copy Path, Details text, and a `Notebook` with `SpectrogramCanvas` (PPM image plus cut-off markers) and `SpectrumCanvas`. After each scan `SummaryDialog` shows a donut chart (Canvas arcs, percentages on slices of 7 % or more, the problem share in the centre) with a legend. Clicking a slice or a legend row calls `set_filters([verdict])`, and `SettingsDialog` builds its tabs from `Settings.field_info()`. Keys: Enter/double-click for the primary action, Ctrl/Cmd+Enter for the secondary one, Ctrl+C to copy, Ctrl+O to add a folder, and Ctrl+, for settings. |
| `packaging/realhires.spec` | PyInstaller spec. ## Detection tunables (`realhires/analysis.py` defaults, user-adjustable in `realhires/settings.py`)

Users change these in the GUI Settings window or with CLI `--set` (the settings name is given in brackets). The module constants are the defaults and must stay equal to the `Settings` defaults, which `test_settings_defaults_match_detection_constants` enforces. If you add a tunable, add it in both places and to `detection_params()`.

| Constant | Value | Meaning |
| --- | --- | --- |
| `CLIFF_DB` / `CLIFF_STRONG_DB` (`cliff_db` / `cliff_strong_db`) | 25 / 40 dB | The level drop from 88–96 % to 102–112 % of a candidate source Nyquist that means "upsampled", at medium and high confidence. |
| `EDGE_RATIO` (`edge_ratio`) | 0.98 | When several candidates pass `CLIFF_DB`, pick the one whose Nyquist best matches (−20 dB point ÷ Nyquist ≈ 0.98). |
| `STEEP_DROP_DB` (`steep_drop_db`) | 20 dB | The drop across the bandwidth edge that counts as a brick wall, used by the fallback upsample rule. |
| `LOSSY_CLIFF_DB`, `LOSSY_MIN_HZ`, `LOSSY_MAX_HZ` (`lossy_cliff_db`, `lossy_min_khz`, `lossy_max_khz`) | 25 dB, 11 kHz, 20.3 kHz | The lossy-encoder low-pass search, which gives FAKE LOSSLESS. |
| `CONTENT_MARGIN_DB` (`content_margin_db`) | 10 dB | How far content must sit above the floor reference. |
| `RELEVANT_RANGE_DB` (`relevant_range_db`) | 110 dB | Content further below the spectral peak than this is ignored, which drops resampler images. |
| `ULTRASONIC_HZ` (`ultrasonic_khz`) | 24.5 kHz | A high-rate file with bandwidth below this and no cliff is SUSPICIOUS. |
| `BIT_THRESHOLD` (`bit_threshold_pct`) | 0.5 % | The share of samples needed for a bit position to count as used. |

Candidate source rates are limited to `rate * 1.5 <= file_rate`, so a 96 kHz file is never accused of being upsampled from 88.2 kHz.

## Conventions and gotchas

- ffmpeg output is always `-f s32le -acodec pcm_s32le`. The bit-depth test relies on ffmpeg left-justifying integer samples, and on float-to-s32 conversion being undithered, which is the swresample default.
- Always call FFmpeg through `probe.tool("ffmpeg")` / `tool("ffprobe")` with `**_no_window()`, never through a bare `"ffmpeg"` string, or the packaged builds break.
- Spectrum levels are per bin and normalised so that a full-scale sine reads 0 dB. They are therefore much lower (about -60 dB for music, about -180 dB for a 24-bit floor at a 16k FFT) than the levels shown by spectrum viewers with small FFTs. `quantization_floor_db()` gives the theoretical floor.
- `analyze_file()` must never raise. Any exception becomes `verdict=ERROR` with the message in `reasons`.
- `FileResult.spectrum` holds large arrays. It is only kept for `--plot` and is cleared after plotting. `FileResult.plot` is the small GUI version. Anything that the estimated-resolution logic needs must be copied onto `FileResult` fields, never read from `spectrum`.
- GUI worker processes use the **spawn** context, so any script that starts the GUI must guard its code with `if __name__ == "__main__":`. Otherwise every worker re-runs the script and opens another window. Frozen entry points must call `multiprocessing.freeze_support()` first.
- Every external program must be started with `probe.external_env()` (it is included in `_no_window()`). A frozen Linux build sets `LD_LIBRARY_PATH` to its bundled libraries, and a system ffmpeg or `xdg-open` that inherits it loads the bundle's old `libstdc++`/`libX11` and crashes.
- Linux packages must stay buildable on glibc 2.28, because CI enforces it. Do not add `MAX_GLIBC` exceptions. Instead, find out why a library needs a newer glibc. The spec deliberately leaves out `libfontconfig`/`libfreetype` so that the desktop's own copies are used, because an old bundled fontconfig cannot parse newer configs. Frozen Tk also needs the system `libxcb`, which every X11/XWayland desktop has.
- macOS minimums are declared through `REALHIRES_MACOS_MIN` (into `LSMinimumSystemVersion`) and verified by `check_compat.py`. If a dependency raises its minimum, CI fails, and you must then either raise the documented minimum (README, RELEASE_NOTES, README-RELEASE, the workflow) or pin the dependency.
- Do not edit `Info.plist` or any file inside the built `.app` after PyInstaller has signed it, because that breaks the ad-hoc signature and Apple Silicon then reports the app as "damaged".
- Never create a `ProcessPoolExecutor` directly. Use `pool.MultiProcessPool(effective_jobs(...))`, otherwise Windows users with more than 61 jobs get a `ValueError`. Settings `jobs` is 0..512, where 0 means automatic.
- `fix.run_fix` must never lose user files unless the user chose "Delete it (no backup)", which the GUI confirms. It uses unique backup and copy names, writes to a temp file before moving the original, and puts the original back if the final rename fails. Keep the tests for tags, replace mode and the backup folder passing.
- Executable names must not differ only by case (`RealHiRes` vs `realhires`), because Windows and macOS file systems are case-insensitive. That is why the CLI in packages is `realhires-cli`.
- On Linux the GUI uses the `clam` ttk theme, whose progress bar is invisible by default, so `main()` sets an explicit bar colour.
- You can test the GUI headlessly with `xvfb-run` and take screenshots with ImageMagick `import -window root out.png`. Without a display, `gui.main()` prints a clear message and returns 1.
- Local Linux package builds: inside the cloud dev container, dockerd can be started and `almalinux:8` run with `--network host`, with the proxy CA mounted and the repo `baseurl` used instead of `mirrorlist`.
- The tests must stay self-contained. Generate audio in fixtures instead of committing audio files. They must pass with both the distro FFmpeg and the bundled BtbN/Riedl builds used in CI.
- Always use full, specific sentences in user-facing reasons, because they are printed verbatim in the CLI and the GUI. Keep each `summary` to one short line (under about 70 characters), because it fills the "Why" column.
- New verdict strings must be added to `VERDICT_ORDER`, `settings.ALL_VERDICTS`, `gui.VERDICT_STYLE`, `report._COLORS` and the README verdict table.
- Settings are passed to worker processes by pickling, so `Settings` must stay a plain dataclass. Changing a field name breaks users' saved files only softly (the value falls back to its default), but document the change in the changelog.
- CLI output must survive legacy consoles. A Windows cp1252 console cannot encode `→`, `█` or Japanese file names, and CI caught a crash from exactly that. `report.setup_console()` (called first in `cli.main`) replaces unencodable characters and writes UTF-8 when output is redirected, and `report.arrow()`/`bar_char()` fall back to ASCII. Any new non-ASCII output must go through the same path. `test_cli_survives_legacy_console_encoding` and the smoke test's Japanese file name guard this.
- Do not use emoji in Tk widget text. Several Linux fonts cannot render them (the folder glyph showed as a box).
